What works — and what doesn't
On Intel consumer platforms the CPU root complex cannot route BAR-mapped peer TLPs between different PCIe root ports. This is a silicon-level decision, not fixable in software. Here's exactly what that means for inference.
💡
The bottom line: you don't need working BAR P2P for multi-GPU inference. NCCL automatically falls back to shared-host-memory (SHM) transport, and vLLM automatically disables custom all-reduce. Both adapters detect the limitation and work around it — no flags needed. The only requirement is the patched NVIDIA driver to enable the cudaMemcpyPeer DMA path.
✕ Fails

Direct BAR P2P

GPU-to-GPU memory access via PCIe BAR windows causes silent data corruption (NaN tensors). The root complex accepts the TLP but drops or misroutes it.

✕ Fails

CUDA IPC

Cross-process BAR mapping fails for the same reason. vLLM's can_actually_p2p() spawns separate processes, catches the failure, and disables custom all-reduce.

✕ Misleading

ACS registers

setpci writes succeed with exit 0, but the registers read back 0xffff. ACS state doesn't matter — the root complex can't route P2P regardless.

✓ Works

cudaMemcpyPeer

DMA staging through host RAM delivers ~6 GB/s. Requires the patched open-source NVIDIA driver — the stock driver blocks the peer DMA path.

✓ Works

NCCL SHM transport

NCCL probes at startup, detects the P2P failure, and auto-selects shared-host-memory. You'll see via SHM/direct/direct in the logs. No config changes needed.

✓ Works

vLLM TP=2

Full tensor parallelism across two consumer GPUs. Sets all-reduce is delegated to NCCL automatically. Tested with Qwen3.6-35B-A3B-FP8 and Qwen3.5-9B.

✓ Works

Ollama multi-GPU

Ollama uses the same cudaMemcpyPeer DMA path. A three-line systemd drop-in pins it to the best GPU pair with OLLAMA_NUM_GPU=2.

✓ Auto-safe

apt upgrade

DKMS rebuilds the patched modules every time a new kernel lands. An apt pin + apt-mark hold blocks the stock driver from slipping back in. Fully unattended.

PCIe topology
Test rig: Intel i7-12700KF (Alder Lake) with 5 NVIDIA GPUs. Every GPU sits on its own root port — no PLX switch. The DMI bridge is the shared bottleneck for PCH-attached cards.
lspci topology — /proc/bus/pci · Bus 00
# ── CPU PEG lanes (direct to root complex, no bridge crossing) ──
  00:01.0  →  [01]  EMPTY SLOT              x16 electrical
  00:01.1  →  [02]  GPU0: RTX 3090  24 GiB   Gen4 x8  · ~6.6 GB/s ✓ best pair candidate

# ── PCH lanes (every transaction crosses DMI 3.0 x4 · ~16 GB/s shared) ──
  00:1b.4  →  [04]  GPU1: RTX 3090  24 GiB   Gen4 x4  · ~6.6 GB/s ✓ best pair candidate
  00:1c.0  →  [05]  GPU2: RTX 3060  12 GiB   Gen1 x1  · ~0.8 GB/s ⚠ bandwidth-starved
  00:1c.1  →  [06]  GPU3: RTX 3060  12 GiB   Gen1 x1  · ~0.8 GB/s ⚠ bandwidth-starved
  00:1c.4  →  [08]  GPU4: RTX 3090  24 GiB   Gen4 x4  · ~6.6 GB/s ✓

# Best TP=2 pair: GPU0 (PEG Gen4 x8) + GPU1 (PCH Gen4 x4)
# All-reduce traffic crosses the DMI bridge once per step — fast enough.
⚠
The 3060s physically support Gen3 x16 but the PCH ran out of lanes — they negotiate Gen1 x1 (~0.8 GB/s). Run python3 scripts/p2p_bandwidth_bench.py before choosing your TP=2 pair. The script flags under-threshold pairs and prints the relevant lspci command to investigate.

Environment variables
Two variables cover everything. Set them once in your launch script; the installer's manage_vllm_safe_tp2.sh already includes both.
Production — fastest
NCCL_P2P_DISABLE =1
VLLM_SKIP_P2P_CHECK =1
Skips P2P probing entirely. NCCL goes straight to SHM and optimizes it aggressively. VLLM_SKIP_P2P_CHECK=1 saves ~5 s on cold start by bypassing P2P cache generation. Use this once you've verified the setup works.
Initial validation — first run only
NCCL_P2P_DISABLE =0
VLLM_SKIP_P2P_CHECK =0
Lets NCCL probe and fall back (confirms via SHM in logs). Lets vLLM run its IPC test and disable custom all-reduce (confirms the warning message appears). Run once to verify, then switch to production.
✕
Don't use --disable-custom-all-reduce. vLLM disables custom all-reduce automatically when P2P isn't available. Adding the flag manually is redundant and can mask the auto-detection log message that confirms everything is working correctly.
What the installer does
python3 install.py shows a plan, asks for confirmation, then launches a full-screen animated display while all of this runs in the background. Use --dry-run to preview without changes.
1
Bootstrap & preflight
Installs asciimatics if missing, checks for root, verifies CUDA is present, and previews the full change plan before touching anything.
2
Clone patched NVIDIA driver
Clones aikitoria/open-gpu-kernel-modules branch 595.58.03-p2p — the fork that enables the cudaMemcpyPeer DMA path on consumer hardware.
3
Register with DKMS
Signs the modules with your MOK key (Secure Boot compatible) and registers them with DKMS. Every future apt kernel upgrade triggers an automatic rebuild before reboot.
4
Patch GRUB + modprobe
Appends intel_iommu=on iommu=pt pci=noaer pcie_aspm=off to GRUB and writes /etc/modprobe.d/nvidia.conf with RMForceP2PType=0.
5
apt lockdown
Creates /etc/apt/preferences.d/00-nvidia-p2p-pin with Pin-Priority: -1 and runs apt-mark hold on all nvidia-* / libnccl* packages. apt upgrade can never replace the patched driver.
6
Stash .run installer
Copies the .run installer to /opt/nvidia-p2p/ for disaster recovery, then installs /usr/local/sbin/p2p-healthcheck for post-reboot validation.
7
vLLM environment
Creates ~/venvs/vllm and installs the full CUDA 12.8 vLLM stack via uv. Isolated from system Python, reproducible, and pinned to a known-good version.

Scripts
Production-ready utilities for launching, validating, and benchmarking. All scripts are in scripts/.
ScriptPurpose
install.py Interactive autoinstaller — full-screen animated UI, plan preview, handles every step end-to-end
manage_vllm_safe_tp2.sh Production vLLM launcher with boot arg gates. Commands: start / stop / restart / status / health
require-gpu-pair.sh Pre-flight check that validates the TP=2 GPU pair is present and healthy before launching vLLM
post-reboot-test.sh Full post-reboot validation suite: boot args, NCCL all-reduce, P2P paths, driver version
test_nccl_tp2.py Standalone NCCL all-reduce test across two GPUs using SHM transport — quick sanity check
p2p_bandwidth_bench.py Full P2P + PCIe bandwidth benchmark. Compiles the CUDA source, runs all GPU pairs, emits a reproducible system report with driver version, nvidia-smi topo, and lspci output
p2p_bandwidth_bench.cu CUDA source: unidirectional bandwidth, bidirectional bandwidth, round-trip latency, P2P vs CPU-bounce comparison — all GPU pairs
