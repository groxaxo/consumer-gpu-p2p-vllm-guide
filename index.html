RTX 3090 · Linux · vLLM

Peer access that must prove itself.

A fail-closed installation and validation path for patched NVIDIA consumer-GPU P2P. Driver capability reports are not accepted as correctness evidence.

Version-specific kernel work: the reviewed patch requires matching NVIDIA 595.58.03 userspace, IOMMU passthrough, DKMS, a reboot, and destructive peer-memory tests.

Why version 2 exists

Exact driver match

The installer refuses to combine patched 595.58.03 kernel modules with another NVIDIA userspace version.

Real memory access

Kernels on every selected GPU directly read and write exact patterns in every peer GPU's allocation.

vLLM's own IPC test

VLLM_SKIP_P2P_CHECK=0 remains enabled. Cross-process CUDA IPC is tested rather than trusted.

Machine-bound profile

Kernel, driver, GPU UUID/order, PCI bus, and boot changes invalidate the profile and block launch.

Install

git clone https://github.com/groxaxo/consumer-gpu-p2p-vllm-guide.git
cd consumer-gpu-p2p-vllm-guide

python3 install.py \
  --driver-runfile "$HOME/Downloads/NVIDIA-Linux-x86_64-595.58.03.run" \
  --install-userspace \
  --lock-driver \
  --yes

sudo reboot

Validate, then launch

CUDA_VISIBLE_DEVICES=0,1 bash scripts/post-reboot-test.sh

# Only after RESULT=PASS:
CUDA_VISIBLE_DEVICES=0,1 \
  bash scripts/manage_vllm_safe_tp2.sh start <model-id>

Validated runtime: NCCL_P2P_DISABLE=0, NCCL_SHM_DISABLE=0, VLLM_SKIP_P2P_CHECK=0.

Three RTX 3090s

The validator can test all three cards in every direction. NCCL can use validated P2P for TP=3, while vLLM custom all-reduce remains unavailable at world size 3. TP=2 and TP=3 are therefore reported separately rather than conflated.

Explicit fallback

VLLM_P2P_MODE=shm \
  bash scripts/manage_vllm_safe_tp2.sh start <model-id>

SHM mode disables NCCL P2P and vLLM custom all-reduce. It preserves a correct recovery path, but it is never labelled P2P.
